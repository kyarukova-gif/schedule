# Как устроена запись с оплатой (Stripe + Netlify + письма)

Описание системы записи на рождественские фотосессии на Marché de Noël (Ницца). Документ написан так, чтобы по нему можно было собрать **такой же лендинг с другой оплатой**: в конце есть раздел «Как переделать под другой лендинг» и заготовка задания для Claude.

Исходный код: репозиторий `kyarukova-gif/schedule`, ветка `claude/charming-davinci-53ag6d`, папка `booking/`. Все секреты (ключи) в код не входят, они лежат только в переменных окружения Netlify.

---

## 1. Коротко

- **Что делает:** клиент выбирает тариф, день и время, оставляет контакты, платит предоплату 20 € картой, Apple Pay, Google Pay или PayPal. После оплаты время закрывается за ним автоматически, фотографу и клиенту приходят письма.
- **Из чего собрано:** статическая страница (`index.html`) + одна серверная функция Netlify (`/api/*`) + Stripe Checkout (платёжная страница Stripe) + хранилище Netlify Blobs (занятые слоты) + два канала писем (Resend фотографу, Gmail клиенту).
- **Что НЕ используется:** собственная база данных, WordPress, Stripe Payment Links, готовые плагины записи. Вся логика (слоты, проверка, письма) написана своим кодом, около 600 строк.
- **Хостинг:** один сайт Netlify на всё: и страница, и сервер. Деплой автоматический из GitHub.

## 2. Схема

```
Клиент (телефон)
   │ 1. открывает страницу: GET /  и  GET /api/config  (дни, цены, занятые слоты)
   │ 2. выбирает тариф/день/время, вводит имя, Instagram, телефон, email, пожелания, ставит галочку
   │ 3. POST /api/checkout  ───────────────────────────────┐
   ▼                                                       ▼
Страница (index.html)                    Netlify Function «api» (netlify/functions/api.mjs → lib/core.mjs)
                                          • проверяет данные на сервере
                                          • ДЕРЖИТ слот(ы) 31 минуту (Blobs, статус "held")
                                          • создаёт Stripe Checkout Session (20 €) ─────► Stripe API
                                          • возвращает ссылку на оплату
   │ 4. браузер уходит на страницу оплаты Stripe (карта / Apple Pay / Google Pay / PayPal)
   ▼
Stripe ── клиент платит ──► Stripe шлёт событие  POST /api/webhook  (подписанное)
                                          ▼
                              Netlify Function «api»:
                               • проверяет подпись Stripe (HMAC-SHA256)
                               • checkout.session.completed → слот(ы) становятся "booked" НАВСЕГДА
                               • письмо фотографу (Resend) + письмо клиенту (Gmail/SMTP)
                               • checkout.session.expired → слот освобождается (неоплаченный)
   │ 5. Stripe возвращает клиента на /?paid=1  → экран «Вы записаны!» + кнопка гайда
```

Главная идея: **истина об оплате приходит от Stripe через webhook, а не от браузера клиента.** Страница «Вы записаны!» только для красоты. Слот закрывается, только когда Stripe сообщил об оплате.

## 4. Путь клиента на странице (index.html)

Шаги (порядок на странице):
1. **Сколько вас и на сколько:** счётчик числа людей (1–15) и выбор тарифа (30 мин за 100 € или 60 мин за 190 €). С 4 человек появляется подсказка «лучше час» (только совет, не запрет).
2. **День** (карточки дней с числом свободных времён).
3. **Время** (кнопки; занятые серые и зачёркнутые). Показываются только те начала, где съёмка помещается в рабочий день.
4. **Ваши данные:** имя, Instagram (проверка формата), телефон (проверка), **email** (обязателен, подставляется в Stripe), пожелания (необязательно).
5. **Проверка и оплата:** итог (когда, сколько человек, цена, остаток на месте, к оплате сейчас 20 €), пояснение про предоплату, **галочка согласия** (текст про невозвратность, отсутствие права отказа в 14 дней, ссылка на условия), блок про погоду/перенос. Кнопка «Оплатить 20 € и забронировать» закреплена внизу экрана.

Технически:
- Страница сама ничего не считает «на доверии»: при открытии делает `GET /api/config` и рисует всё по ответу сервера. Занятые слоты берутся оттуда же и обновляются при возврате на вкладку и после ошибки «время занято».
- Тексты лежат в объекте `T` на трёх языках (ru, en, fr), язык выбирается по браузеру и кнопкам вверху, запоминается в `localStorage`.
- Кнопка оплаты делает `POST /api/checkout` с выбранным слотом и данными. Ответ: `{ url }` (ссылка на Stripe) и страница переходит по ней. Ошибки: `409` «время только что заняли» (список слотов обновляется), `400` с кодом поля (подсвечивается нужное поле), остальные показываются общим сообщением.
- **Экран после оплаты:** Stripe возвращает на `/?paid=1&slot=…`, страница показывает «Вы записаны!», выбранное время и кнопку «Гайд по съёмке» (PDF на языке клиента).
- **Плеер под шапкой:** видео по очереди (рамка подстраивается под формат ролика), затем показ фото; касание — следующий пункт; видео без звука, автозапуск, пауза вне экрана; уважает `prefers-reduced-motion`. Список файлов берётся из `config.js`.
- Оформление: гирлянда и снег (canvas) в шапке, тёмно-зелёная палитра, карточки цвета «крем». Всё только на встроенном CSS, без фреймворков.

## 5. Серверная часть: три маршрута (netlify/lib/core.mjs)

Функция Netlify v2 принимает всё, что идёт на `/api/*` (в `api.mjs`: `export const config = { path: "/api/*" }`). Дальше `core.mjs` сам разбирает путь.

### 5.1 `GET /api/config`
Отдаёт странице **только то, что ей нужно:** тарифы, дни и часы, число людей, шаг сетки, часовой пояс, Instagram, список занятых слотов и «сейчас» по часовому поясу съёмок. Контакты, ссылки на гайд, WhatsApp и прочее **намеренно не отдаются**.

### 5.2 `POST /api/checkout` (создание оплаты)
Порядок действий:
1. **Валидация на сервере** (страница проверяет то же самое, но верить ей нельзя): тариф существует; день из списка; время попадает в сетку и съёмка помещается в рабочий день; время не в прошлом (по часовому поясу съёмок); имя; Instagram (формат); телефон (7–15 цифр); email (формат); число людей 1–15; пожелания обрезаются до 400 символов.
2. **Проверка и удержание слота:** для выбранного времени вычисляются «ячейки» сетки (см. раздел 6). Если хоть одна занята: `409`. Иначе все ячейки записываются как `held` на 31 минуту.
3. **Создание Stripe Checkout Session** запросом `POST https://api.stripe.com/v1/checkout/sessions` (без библиотеки, обычный `fetch`, тело в формате `application/x-www-form-urlencoded`). Что передаётся (см. раздел 7).
4. Если Stripe вернул ошибку, удержание снимается, клиенту `502`. Если успех, в записи удержания сохраняется id сессии, клиенту уходит `{ url }`.

Особенность: сначала запрос уходит с методами оплаты `["card", "paypal"]`. Если PayPal в Stripe не включён и Stripe отклоняет запрос из-за этого, сервер автоматически повторяет запрос только с картой. Так оплата не ломается ни в каком случае.

### 5.3 `POST /api/webhook` (событие от Stripe)
1. **Проверка подписи.** Берётся «сырое» тело запроса и заголовок `stripe-signature`; считается HMAC-SHA256 от `<timestamp>.<тело>` секретом `STRIPE_WEBHOOK_SECRET`; сравнение без утечки по времени; допуск по времени 5 минут. Подпись неверна: `400`. Без этого любой мог бы «сообщить» об оплате.
2. События без `metadata.slot` (например, платежи других продуктов того же аккаунта Stripe) **молча игнорируются** с ответом `200`.
3. `checkout.session.completed` и `checkout.session.async_payment_succeeded` (если платёж реально `paid`): все ячейки времени записываются как `booked` навсегда; в главной ячейке лежит полная запись брони (имя, Instagram, телефон, email, пожелания, цена, язык и т.д.). Потом уходят письма (раздел 8).
4. `checkout.session.expired` и `checkout.session.async_payment_failed`: удержание **снимается**, но только если оно принадлежит именно этой сессии (чужую бронь не тронет).
5. **Идемпотентность:** Stripe может прислать одно событие несколько раз. В записи брони есть флаги `emailed`, `clientEmailed`, `clientMailV`. Повторное событие ничего не делает, если письма уже ушли. Если письмо не отправилось (ошибка), сервер отвечает `500`, Stripe повторяет событие позже, и отправка добирается, но бронь и письмо фотографу заново не дублируются.

## 6. Слоты: как не допустить двойной брони

- **Сетка времени:** в рабочем дне время идёт с шагом `slotMinutes + bufferMinutes` (30 + 5 = 35 минут): 12:00, 12:35, 13:10 и т.д. Между съёмками получаются 5 минут запаса.
- **Ячейки:** съёмка на 30 минут занимает 1 ячейку, на 60 минут 2 подряд (10 минут запаса вместо 5). Ключ ячейки: `slot:2026-12-11 12:35`.
- **Состояния ячейки:**
  - нет записи: свободно;
  - `held` (удержание): на 31 минуту, пока клиент платит; истекает само (TTL) или снимается событием `expired`;
  - `booked`: оплачено, навсегда.
- **Где хранится:** Netlify Blobs (хранилище `slots`). Блобы не умеют TTL, поэтому `kv.mjs` пишет `{ v: значение, exp: время_истечения }` и при чтении сам считает просроченное удалённым. Интерфейс адаптера повторяет Cloudflare KV (`get / put с expirationTtl / delete / list`), поэтому ядро не привязано к конкретному хранилищу.
- **Гонки:** проверка «свободно» и запись «удержание» идут двумя запросами, а не атомарно. Для потока в единицы записей в день этого достаточно (два клиента в ту же миллисекунду маловероятны). Для высокой нагрузки нужна атомарная операция (Durable Object, условная запись и т.п.).
- Освобождение слота вручную: Netlify → Data & storage → Blobs → `slots` → удалить запись `slot:…`. **Возврат денег в Stripe слот сам не освобождает.**

## 7. Stripe: что настроено и что передаётся

### Что настроено в аккаунте Stripe
- **Webhook (Developers → Webhooks → Add destination):**
  - адрес: `https://<ваш-сайт>.netlify.app/api/webhook`;
  - стиль данных: Snapshot;
  - события (всего 4): `checkout.session.completed`, `checkout.session.expired`, `checkout.session.async_payment_succeeded`, `checkout.session.async_payment_failed`;
  - выдаёт **Signing secret** (`whsec_…`) → переменная `STRIPE_WEBHOOK_SECRET`.
- **Ключ для сервера:** в боевом режиме создан **ограниченный ключ** (Developers → API keys → Create restricted key → «Powering an integration you built» → шаблон прав **One-time payments**), он начинается с `rk_live_`. Серверу нужно только право создавать Checkout Sessions. Ключ показывается один раз → переменная `STRIPE_SECRET_KEY`.
- **Способы оплаты** (Settings → Payment methods): карта, Apple Pay, Google Pay, PayPal включены. Сервер явно запрашивает `card` и `paypal`.
- **Тестирование:** отдельно в песочнице («Sandbox» / Test mode) создаются **свои** тестовый webhook и ключ `sk_test_…`. Боевой и тестовый режимы полностью раздельны: ключ и подпись одного не работают в другом. Тестовая карта: `4242 4242 4242 4242`.

### Что передаётся в Checkout Session
| Параметр | Зачем |
|---|---|
| `mode: payment` | разовая оплата |
| `payment_method_types: [card, paypal]` | карты (с Apple/Google Pay) и PayPal |
| `line_items[0].price_data` (валюта eur, сумма предоплаты в центах, название) | товар задаётся «на лету», **в каталоге Stripe создавать ничего не нужно** |
| `metadata` (slot, lang, minutes, people, price, deposit, name, instagram, phone, wishes) | все данные клиента видны в платеже и приходят в webhook |
| `payment_intent_data.metadata` и `description` | то же самое на уровне платежа, видно в списке Payments |
| `customer_email` | подставляет почту клиента и отправляет ему чек Stripe |
| `custom_text.submit.message` | текст под кнопкой оплаты: что за предоплата, невозвратность, нет права отказа, правило переноса, ссылка на условия |
| `locale` | язык платёжной страницы по выбору клиента (ru/en/fr) |
| `expires_at` | сессия живёт 30 минут 30 секунд (Stripe требует не меньше 30 минут) |
| `success_url` / `cancel_url` | возврат на `/?paid=1&slot=…` или на `/` |
| `client_reference_id` | метка `дата_время` для удобства в Stripe |

Что видит владелец в Stripe: платёж 20 €, в его карточке вкладка Metadata с именем, Instagram, телефоном, временем, пожеланиями.

## 8. Письма

Письма идут **двумя независимыми каналами**, потому что у них разные ограничения.

### 8.1 Фотографу (Resend)
- Простое HTML-письмо со всеми данными брони (когда, сколько человек, имя, Instagram, телефон, email клиента, пожелания, стоимость и остаток). В поле «ответить» стоит почта клиента.
- Отправка через HTTP API Resend (`POST https://api.resend.com/emails`).
- Переменные: `RESEND_API_KEY`, `NOTIFY_EMAIL`, по желанию `MAIL_FROM`.
- **Ограничение Resend без подтверждённого домена:** отправитель `onboarding@resend.dev`, письма можно слать **только на ту почту, с которой зарегистрирован аккаунт Resend**. Для писем владельцу этого достаточно, для писем клиентам нет.

### 8.2 Клиенту (Gmail через SMTP, nodemailer)
- Чтобы писать произвольным клиентам без подтверждения домена, письмо уходит с Gmail-адреса владельца через SMTP с **«паролем приложения» Google** (аккаунт Google → Безопасность → пароли приложений; нужна двухэтапная проверка). Переменные: `GMAIL_USER`, `GMAIL_APP_PASSWORD`.
- Письмо собирает `mail.mjs`:
  - красивое HTML-письмо в стиле страницы (таблицы и инлайновые стили, чтобы работало в почтовых клиентах), на языке клиента (ru/en/fr);
  - заголовок «Спасибо, вы записаны!», детали (дата, время, длительность, число людей, место, пожелания);
  - кнопка **«Добавить в Google Календарь»**: ссылка `calendar.google.com/calendar/render?action=TEMPLATE&…` со временем в UTC (местное время съёмок пересчитывается в UTC функцией `zonedToUtc`);
  - к письму **прикреплён файл `.ics`** для Apple Календаря и Outlook;
  - место встречи, блоки «Что важно знать» (фотографии, оплата, погода и перенос), ссылка на условия, кнопка гайда (на языке клиента), кнопки связи (Instagram, фотопортфолио, почта, WhatsApp);
  - подпись со ссылкой на сайт фотографа.
- **Если нужен «брендовый» отправитель** (например, `hello@вашдомен`), нужно подтвердить домен в Resend (DNS-записи SPF/DKIM) и слать клиентам через Resend; архитектура допускает такую замену, меняется только функция `sendClientMail` в `api.mjs`.

### 8.3 Защита от повторных писем
- В записи брони хранятся `emailed` (письмо владельцу ушло), `clientEmailed` (письмо клиенту ушло), `clientMailV` (версия письма).
- Повтор события Stripe ничего не отправляет заново.
- Повторная отправка по существующей брони (нужна только для проверки нового шаблона на тестовой брони) включается **только** переменной `ALLOW_MAIL_RESEND=1` и увеличением `CLIENT_MAIL_VERSION` в `core.mjs`. Без флага письма по старым броням не уходят никогда.

## 9. Netlify: настройка и переменные

- **Создание сайта:** Add new site → Import from Git → репозиторий → ветка → **Base directory: `booking`** (репозиторий содержит и другой, посторонний сайт в корне).
- **`netlify.toml`** (лежит в `booking/`): `publish = "."`, `functions = "netlify/functions"`, `NODE_VERSION = "22"`, `SECRETS_SCAN_OMIT_KEYS = "GMAIL_USER,NOTIFY_EMAIL"` (почта владельца публична, ловушка раздела 12).
- **Автодеплой:** каждый пуш в выбранную ветку сразу становится боевым.
- **Переменные окружения** (Netlify → Environment variables):

| Переменная | Что это | Секретная |
|---|---|---|
| `STRIPE_SECRET_KEY` | ключ Stripe для создания платежей (`rk_live_…`, в тесте `sk_test_…`) | да |
| `STRIPE_WEBHOOK_SECRET` | подпись webhook Stripe (`whsec_…`) | да |
| `RESEND_API_KEY` | ключ Resend для письма владельцу | да |
| `NOTIFY_EMAIL` | почта, куда приходят письма о записях (та, на которую зарегистрирован Resend) | нет |
| `GMAIL_USER` | Gmail, с которого уходят письма клиентам | нет |
| `GMAIL_APP_PASSWORD` | пароль приложения Google (16 букв) | да |
| `MAIL_FROM` | отправитель письма владельцу (по умолчанию `onboarding@resend.dev`) | нет, необязательно |
| `ALLOW_MAIL_RESEND` | `1` только на время проверки нового шаблона письма | нет, обычно не задана |
| `URL` | адрес сайта, **Netlify подставляет сам**, нужен для ссылок в письмах и возврата из Stripe | задавать не нужно |

- После изменения переменных нужна пересборка (Deploys → Trigger deploy).
- **Хранилище слотов** подключается автоматически в функции Netlify v2 (`getStore("slots")`), настраивать ничего не нужно.

## 10. Юридические и деловые решения, зашитые в систему

Это решения владельца, а не юридическая консультация. Проверка по первоисточникам (Légifrance) не проводилась, опора на пересказы.

- 20 € оформлены как **предоплата (arrhes)**, которая резервирует время и засчитывается в стоимость. Невозвратна, если клиент отменяет съёмку. Если не по погоде и не форс-мажору отменяет исполнитель, предоплата возвращается (в условиях так и написано).
- **Нет права отказа в 14 дней** для съёмки на конкретную дату (ссылка на ст. L221-28, 12° Code de la consommation). Это сообщается клиенту до оплаты: в галочке согласия, в тексте у кнопки Stripe, в условиях. Применимость к фотосъёмке не подтверждена ни одним найденным источником.
- **Погода:** съёмка переносится по договорённости; если ни одно время не подходит, предоплата возвращается.
- **Перенос по форс-мажору:** не позднее чем за 24 часа до съёмки, это именно перенос, а не отмена (предоплата засчитывается за новое время).
- **Условия (CGV) и mentions légales:** `cgv.html` на английском и русском (основные) и французском (для информации): реквизиты предпринимателя, цены, предоплата, перенос, медиатор по потребительским спорам, персональные данные, применимое право.
- **Персональные данные:** собираются имя, Instagram, телефон, email, число людей, пожелания; обрабатывают Stripe, Netlify (хостинг и хранилище), Resend и Gmail. Об этом написано в условиях.

## 11. Безопасность

- Секретных ключей в коде и репозитории нет. Они только в переменных Netlify; секретные помечены как «Contains secret values».
- Сервер **не верит странице:** цена, тариф, время, количество людей проверяются заново; цена берётся из `config.mjs` на сервере, а не из запроса.
- Подпись webhook проверяется всегда; без неё бронь не создаётся.
- Публичный `/api/config` отдаёт минимум (без контактов и ссылок для писем).
- Любой пользовательский текст, попадающий в HTML письма, экранируется (`esc`).
- Ограниченный боевой ключ Stripe (не полный секретный) уменьшает ущерб при утечке.
- Что **не** защищено: нет защиты от «забивания» слотов ботом (удержание на 31 минуту без оплаты); при необходимости добавить ограничение частоты запросов или капчу.

## 12. Грабли, на которые мы наступили (и решения)

1. **Проверка секретов Netlify сломала сборку.** Netlify сканирует сборку на значения секретных переменных; почта владельца (`GMAIL_USER`) публично есть в условиях и конфиге, поэтому сборка упала «утечкой». Решение: `SECRETS_SCAN_OMIT_KEYS = "GMAIL_USER,NOTIFY_EMAIL"` в `netlify.toml`. При этом упавшая сборка не публикуется, сайт продолжает работать на прежней версии.
2. **Секретные переменные Netlify** нельзя задать «одним значением для всех контекстов»: значение нужно вписать в поле **Production**. Сначала мы по ошибке вписали сами ключи в поле **Key**; в поле Key всегда **имя** переменной.
3. **Safari может автозаполнить** поле Key почтой. Проверять поле перед сохранением.
4. **В боевом режиме Stripe секретный ключ часто уже скрыт**, поэтому создаётся ограниченный ключ (`rk_live_`) с шаблоном «One-time payments» (в нём есть Checkout Sessions Write).
5. **Тестовый и боевой режимы Stripe раздельны:** нужен отдельный webhook и отдельный ключ в каждом. В Netlify при переходе на боевой режим меняются оба значения (`STRIPE_SECRET_KEY` и `STRIPE_WEBHOOK_SECRET`).
6. **Возврат платежа слот не освобождает.** Тестовые брони нужно удалять из Blobs вручную. (Идея на будущее: слушать событие `charge.refunded` и освобождать слот.)
7. **Resend без домена пишет только владельцу аккаунта.** Для клиентов используется Gmail с паролем приложения.
8. **Письма по уже существующим броням заново не уходят**, поэтому при правке шаблона на пробной брони нужен `ALLOW_MAIL_RESEND=1` + увеличение версии (и потом выключить).
9. **PayPal:** он должен быть включён в Stripe; код сам откатывается на карты, если не включён.
10. **Кодировка:** публичный ответ API без `charset=utf-8` показывался «кракозябрами» (на странице всё было нормально); исправлено заголовком.
11. **Кнопка «Resend» в Stripe** повторяет доставку события; из-за идемпотентности письма заново не отправятся, пока не включён флаг из п. 8.
12. **Ключи и подписи попадали на скриншоты** в процессе настройки. Всё, что попало, считать скомпрометированным (особенно настоящий ключ Resend): перевыпустить.

## 13. Тесты

`node netlify/test.mjs` (без сети, на подставных Stripe/почте/хранилище). Проверяют:
- валидацию всех полей и граничные случаи (время не по сетке, час не влезает, 0 и 99 человек);
- удержание слота, конфликт второй брони, закрытие после оплаты, освобождение при `expired`, неприкосновенность оплаченной брони;
- 60-минутная бронь занимает две ячейки и корректно конфликтует;
- подпись webhook (неверная отклоняется);
- письмо владельцу один раз, повторы события не шлют лишнего, повтор после сбоя отправки добивается;
- письмо клиенту: получатель, тема на нужном языке, наличие `.ics`; отдельный повтор после сбоя; без флага повторной отправки не шлётся;
- PayPal запрашивается; при отказе Stripe откат на карты;
- публичный `/api/config` не содержит контактов;
- адаптер хранилища Netlify Blobs: TTL, список, неистекающие брони.

Полная проверка в браузере (отдельным скриптом): выбор слота → оплата → закрытие слота → письмо.

## 15. Как переделать под другой лендинг с другой оплатой

### Что остаётся без изменений (переиспользуется)
- Схема «страница → `/api/checkout` → Stripe Checkout → webhook → письма».
- Проверка подписи webhook, идемпотентность, флаги отправленных писем.
- Хранилище Blobs и адаптер `kv.mjs`.
- `api.mjs` (подключение хранилища, переменных, Gmail).
- Каркас `index.html`: переключатель языков, валидация форм, блок оплаты, экран после оплаты.
- Тесты как образец.

### Что меняется в зависимости от нового лендинга
| Вопрос | Что менять |
|---|---|
| **Что продаёте** (товар, курс, консультация, билет) | `line_items`/`price_data` в `handleCheckout`, тексты, поля формы |
| **Нужно ли время/слоты?** | Если нет (например, продажа без записи): удалить блок слотов (`cellKeys`, `startOk`, удержание в Blobs), оставить только создание платежа и webhook. Если есть запись на время, слоты как есть |
| **Сумма:** полная цена, предоплата, несколько тарифов, пакеты | `packages` в `config.mjs` и логика цены в `handleCheckout` |
| **Разовая оплата или подписка** | подписка: `mode: "subscription"` + создать Price в Stripe + другие события webhook (`invoice.paid`, `customer.subscription.*`); разовая оплата: как сейчас |
| **Что видит клиент после оплаты** (доступ, ссылка, файл, код) | письмо клиенту (`mail.mjs`) и экран `?paid=1`; для цифровых товаров код/ссылка генерируется в webhook |
| **Налоги и счета** | НДС (Stripe Tax), счета-фактуры (`invoice_creation` в Checkout), реквизиты в тексте |
| **Страны и валюты** | `currency`, `locale`, способы оплаты; другие методы (SEPA, iDEAL, Klarna и др.) включаются в Stripe и добавляются в `payment_method_types` или не указываются совсем (тогда Stripe берёт включённые в Dashboard) |
| **Юридические тексты** | `cgv.html`, текст согласия, `custom_text` Stripe; при другой юрисдикции они другие, их нужно проверить |
| **Язык и тексты** | объект `T` в `index.html`, `mail.mjs`, `cgv.html` |
| **Каналы писем** | если у владельца есть домен, можно слать письма клиентам через Resend с подтверждённого домена вместо Gmail |
| **Оплата не Stripe** (PayPal как основной, ЮKassa, Mollie, Revolut, СБП и т.п.) | заменить `callStripe`/`verifyStripe` на API выбранного провайдера: создание платёжной сессии и проверку подписи его webhook. Остальное (слоты, письма, страница) почти не меняется |

### Другие варианты оплаты, которые можно подключить
- **Stripe Payment Links:** самый простой вариант, ссылка на оплату без сервера. Минус: нет автоблокировки слотов и данных клиента из формы (только то, что вы настроите в ссылке).
- **PayPal напрямую** (без Stripe): отдельный аккаунт и API. Через Stripe PayPal уже подключён.
- **Apple Pay / Google Pay:** уже работают через карточную оплату Stripe, ничего отдельно делать не нужно.
- **Оплата на месте / переводом:** запись без онлайн-оплаты; тогда удержание слота нужно заменить подтверждением владельца.

## 16. Чего в системе нет (и что можно добавить)

- Нет панели владельца: смотреть брони можно только в Stripe (Payments → Metadata), в письмах и в Netlify Blobs.
- Нет автоматического освобождения слота при возврате платежа (идея: событие `charge.refunded`).
- Нет напоминаний клиентам за день до съёмки и инструмента переноса записи.
- Нет промокодов (Stripe промокод скидывает только сумму предоплаты, а не цену съёмки; нужен промокод на уровне страницы).
- Нет защиты от бота, занимающего слоты (раздел 11).
- Не проверялись тарифы Netlify, Resend и Stripe (по общей информации бесплатных лимитов хватает для небольшого потока); перед запуском нового проекта их стоит перепроверить на сайтах сервисов.
